# Local data contract, version 1

The installed CLI reads a local CSV plus a local provenance JSON. It never
downloads data, opens broker connections or loads a pickle. One asset and one
consistent currency/frequency per input. Nothing is uploaded by this project.

The CSV has exactly these columns:

```csv
Date,Close,AvailableAt
2030-01-02T16:05:00Z,100.0,2030-01-02T16:00:00Z
2030-01-03T16:05:00Z,101.0,2030-01-03T16:00:00Z
```

These two rows illustrate the schema only; they are invented, not market prices.
An experiment requires more observations than its configured windows and splits.

| Field | Contract |
|---|---|
| `Date` | Forecast origin after the close; unique, strictly ascending ISO timestamp with UTC offset or `Z` |
| `Close` | Positive numeric price, or explicit missing value; infinity and zero are rejected |
| `AvailableAt` | When that price became available; timezone required, nondecreasing, never later than `Date` |

The loader normalizes timestamps to UTC. It does not sort, deduplicate, fill
prices, invent availability or infer currency. Missing prices remain in the
original calendar. Targets and label endpoints are constructed before eligible
rows are selected. A horizon of ten means ten source observations, not ten days.
Gaps absent from the input calendar cannot be detected automatically.

Required provenance JSON fields:

```json
{
  "schema_version": 1,
  "symbol": "EXAMPLE",
  "data_kind": "observed",
  "source_url": "https://example.org/replace-with-actual-source",
  "retrieved_at": null,
  "currency": "USD",
  "price_adjustment": "unknown",
  "availability_evidence": "Replace with verifiable publication timing and calendar information.",
  "license": "Replace with the actual source terms, or explicitly state unknown.",
  "redistribution": "Not granted unless verified from the source terms."
}
```

This is a template, not verified provenance. `retrieved_at=null` means unknown,
not today. `price_adjustment` is one of `adjusted`, `unadjusted`, `unknown`,
`synthetic`. Explain the handling of splits, dividends, corrections and currency
conversion in additional metadata. Do not relabel a synthetic fixture as observed
evidence. Record source publication date and the covered period when available.

Timestamp checks verify the supplied record's consistency, not the provider's
truthfulness. The supplier must establish point-in-time authenticity. Raw daily
dates with no known publication timing cannot satisfy this contract merely by
adding a convenient timestamp. For macro inputs, the experimental join in the
core requires release/vintage events; those inputs are not used by the default
price-only model.

## New research versus already inspected history

Use `purpose="new_hypothesis"`, a substantive `selection_note`, explicit
`validation_start`/`test_start`, and `previously_observed_through`. All timestamps
must include a timezone. The new test must begin after the history you already
inspected. AAPL dates through March 7, 2025 are explicitly treated as already seen
because of the archived experiment in this repository. The code cannot know
everything a researcher has seen elsewhere: the declaration is part of the audit.

First create a plan. It records resolved boundaries, configuration, input and code
hashes without fitting. Running observed data requires that matching saved plan:

```sh
volatility-lab plan --config research.json --data data/local/prices.csv --metadata data/local/source.json --plan plans/research.json
volatility-lab run --config research.json --data data/local/prices.csv --metadata data/local/source.json --plan plans/research.json --output runs
```

For rechecking known history, use `purpose="historical_reproduction"`; the output
will say `already_seen`. Neither a new run name nor a different seed makes an old
test an independent holdout. Keep local data and plans out of a public commit
unless their contents and redistribution rights have been separately reviewed.

## Data rights and sources

The default fixture is generated by `synthetic_prices` with fixed variance regimes
and a seeded NumPy generator. Its currency is `SYNTHETIC_UNITS`; its weekday dates
are artificial and do not implement exchange holidays. It uses no third-party
data. Its code and generated example follow the project's licensing notice.

The archived AAPL study used a pre-existing Yahoo Finance/yfinance cache. Its
retrieval date, adjustment metadata and redistribution permission were not
independently established. The cache is excluded from the current release; only
aggregate study errors and methodology are retained. yfinance itself directs
users to Yahoo's data terms and describes the API as intended for personal use.
Consulted October 30, 2026: [yfinance's official documentation](https://ranaroussi.github.io/yfinance/).
Software licensing of a downloader does not grant a license to redistribute its
provider's data.
